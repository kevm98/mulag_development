# Online adaptation — overnight results, 2026-08-29

## 1. The result

**Privileged context beats both wrong-context controls, paired, CIs excluding zero.**

Policy: warm-started from the validated `model_299`, all six context columns
zeroed (so it reproduces the baseline exactly at any context), then fine-tuned
400 iterations with the true 6-D factor vector `e` live in the observation.
Checkpoint `2026-08-29_00-12-48/model_698.pt`, obs width 72.

| comparison | paired median diff | 95% CI | verdict |
|---|---:|---|---|
| privileged vs **mean** | +0.900 mm | [0.20, 1.43] | privileged wins |
| privileged vs **shuffled** | +0.728 mm | [0.22, 1.12] | privileged wins |
| privileged vs zero | +0.650 mm | [-0.11, 1.08] | not significant |

Median lateral 28.52 mm vs the 34.36 mm baseline.

Beating **shuffled** is the load-bearing comparison: identical latent, identical
distribution, only the pairing to the environment's actual plant differs. The
policy is using `e`, not merely benefiting from extra inputs.

Caveats, stated plainly: the effect is small (~3%), it is one mesh and one
seed, and the log-ratio CI includes zero where the median CI does not. This is
a signal that needs replication, not a finished result. The replication run
(3 meshes x 2 seeds) was started and then pre-empted for the over-actuation
work; it is the first thing to re-run.

## 2. The root cause of why the effect is small

`base_at_limit` measures the **frozen Simscape ID model's predicted valve**,
not the policy's action (`mulag_upper_level_env.py:2727-2734`). It sits at
0.73-0.86 across every policy, action_scale (0.001-0.012), lead cap
(0.015-0.060), reward setting and checkpoint tested. Stage 28 already recorded
~89% historical-ID preclip saturation.

A bounded adaptation residual added to a valve command already at its stop is
clipped away — `residual_dead` is ~0.35 everywhere and never moved.

This single fact explains the whole history:
- the adaptation site is closed at the source
- plant variation cannot be compensated when the valve is already saturated
- weakening the actuator *helps* (alpha 0.25 improves tracking 9%) because a
  bang-bang valve overshoots
- neither delay (to 16 steps) nor alpha degrades the task, because a saturated
  valve is insensitive to how it is scaled or delayed

## 3. What was broken and is now fixed

| defect | consequence | status |
|---|---|---|
| evaluator noise floor 22-74% at fixed seed | every prior oracle gate was unmeasurable | fixed: `--paired_arms`, per-env paired |
| privileged-e route: 4 hardcoded obs widths | the decisive experiment could not start | fixed in all 4 places |
| RIF context never wired into the env | delay had no path to the policy | added `_rif_context_observation` |
| trace recorder omitted the 6-D factor draw | Phase 2 had no targets | added |

The evaluator now also records `action_scale` and the derived per-axis row, and
supports `--paired_delay_steps` / `--paired_alpha` for paired G1 sweeps.

## 4. Measurements that did NOT work (all properly paired)

| experiment | result |
|---|---|
| G1 delay 0/2/4/8/16 | no degradation, every CI includes zero |
| G1 alpha 1.0/0.6/0.4/0.25 | alpha 0.25 *improves* 9% (CI excludes zero) |
| action_scale 0.002 / 0.001 | tracking monotonically worse; saturation barely moves |
| lead cap 0.015 / 0.060 | both worse than the 0.030 default |
| rate penalty -1.20 vs -0.30 | -1.20 much worse (96 vs 50 mm) |
| frozen 2-D latent, paired | privileged **7.1% WORSE** than mean, CI [-14.5%, -0.7%] |

That last row is why the old Stage-31 chain never worked: a code carrying ~0.4%
plant identity is noise, and injecting per-env noise is worse than injecting a
constant.

## 5. Claims withdrawn during the night

- "Every actuator perturbation improves the task" — measured at the noise
  floor before the paired instrument existed. Not supported.
- "action_scale is 0.02 and the lead budget is 1.5 steps" — the effective value
  is 0.004 (assigned per stage); the budget is 7.5 steps.
- "the zeroed action-magnitude penalty is a bug" — it is a deliberate, measured
  tradeoff; the repo recommends the rate penalty instead.

## 6. Next, in order

   emits the valve directly. If `base_at_limit` falls, the adaptation channel
   opens and the ~3% gain should grow.
2. **If direct valve is also saturated** (env_cfg notes Gate 0 measured 79.9%),
   use the **command-ROM as the inverse map**: its predicted valve carries all

   factor-conditioned. This is the strongest remaining option.
3. **Replicate the positive** across 3 meshes x 2 seeds.
4. Only then Phase 2 (AAM: history -> e_hat) and Phase 3 (A-RMA fine-tune).

## 7. Method notes that must not be lost

- Never compare across evaluator runs; use the paired flags.
- Report paired medians and log-ratios, not means: the per-env distribution is
  heavy-tailed (median 34 mm, max 468 mm).
- Verify the artifact, not the flag: check `run_manifest.json` for
  `observation_width`, and check WHICH checkpoint an evaluation scored. Five
  separate false conclusions tonight were caught this way.
- `pgrep -f <script>` matches this shell's own command line — verify jobs by
  `docker ps`, not by process name.

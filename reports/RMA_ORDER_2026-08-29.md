# When the adaptation context enters training

Answer: **at PPO Phase 1, iteration 0. Never during distillation, never after
Phase 1 has converged.**

## Why not during distillation

The cylinder DLS teacher **inverts the cylinder Jacobian** (`verge_task/env_cfg.py`):
it is pure kinematics and has no plant model. Its labels are *identical on every
plant*.

So a context carried through distillation is a channel whose value never
correlates with the target. The student would be trained on labels **invariant**
to it -- explicitly taught that the context predicts nothing. That is worse than
omitting it: E4 measured a near-noise latent at **7.1% worse than mean context**
(CI [-14.5%, -0.7%]), because feeding a policy near-noise is worse than feeding
it a constant.

Corollary: **do not randomise the plant during distillation either.** Plant-blind
labels mean randomisation adds label noise and buys nothing. Randomisation
belongs in Phase 1.

## Why not after Phase 1 either

RMA (arXiv 2107.04034) trains the base policy pi(x, a_-1, z) **and** the encoder
mu jointly under RL from the first iteration. There is no "introduce the latent
later" step in the method. A policy that has already converged without z has
settled on a plant-agnostic solution and gets no gradient pressure to use it.

## Why the seam is safe

Distil context-free at 66 wide, then migrate to 70 wide with the four context
columns zeroed. Verified on the real artifact, 2026-08-29:

| | actor | critic |
|---|---|---|
| width | 66 -> 70 | 66 -> 70 |
| context weight abs-max | 0.0 | 0.0 |
| max output diff, context ~ N(0,1) | **0.0** | **0.0** |
| ... at context x1000 | **0.0** | **0.0** |

Exactly zero, not approximately. Phase 1 therefore provably starts from the
distilled policy, and any later gain is attributable to *learning the context*
rather than to relearning the task.

(The earlier 72-wide `prive_warmstart` migration was only checked for
"reproduces baseline to 0.33 mm" and destabilised under fine-tuning; this check
is the stronger one.)

## The order

1. **Distil** — FD pipeline, DLS teacher, DAgger handover
   (`--anneal_fraction 0.70`), NOMINAL plant, 66 wide, no context.
2. **Migrate** 66 -> 70, context zeroed, identity verified as above.
3. **Phase 1 RL** — context live from iteration 0; plant randomised, staged one
   axis at a time. **Mass first**: it is the only axis with measured G1 headroom
   on this stack (+96.8% cut error at 1.5x, CI [+78.0, +120.9], n=176 paired).
   **Delay second**: the only axis with no analytic breaking point, so it
   degrades the response without ever making the command unreachable.
4. **Observability gate** — privileged vs mean / shuffled / zero, paired
   block-44, plus a **null (zero-action) arm**. The null arm is not optional:
   Stage 0 recorded a do-nothing controller *beating* the frozen PPO
   (4.4 vs 7.2 mm) because the selected episodes had 0.03 mm median motion.
5. **Phase 2** — phi(history) -> z_hat, policy frozen, on-policy DAgger.
6. **Phase 3 (A-RMA)** — fine-tune pi on z_hat so it is robust to the
   estimator's actual errors rather than assuming a perfect latent.

## Why distillation had to restart

The only 66-wide checkpoints present were produced on actuator
`idfd_privileged_context`. The gate refuses them, correctly:

> the observation and action contracts are identical between them, so nothing
> else would catch this -- the numbers would describe the wrong plant.

## Concurrent alternative

Ji et al. (RA-L 2022) train the estimator and policy **concurrently**, which
removes the Phase-1/Phase-2 distribution gap entirely and makes the latent
control-relevant by construction. Worth running as the comparison after the
staged version, which is kept first because it gives clean per-phase
attribution for the write-up.

## Step 1 in practice: three defects in the distillation handover

Found by running it, not by reading it.

**a) The context slot is mandatory on this actuator.** `PpoIDAAMFDEnv` raises
"PPO_AAM_FD requires z_hat in the policy observation" -- it is definitional
for `id_aam_fd`, so a context-free 66-wide distillation is not available. Fixed
by distilling directly at **70 wide with the RMA context on a nominal plant**,
where `normalized_context` maps nominal to exactly zeros. This removes the width
migration step entirely -- and with it the artifact that destabilised before.

**b) Every DAgger update was rejected.** The recovery trigger compares
`student_control_mean_abs_action_label_error` against
`--student_error_recovery_threshold` (default **0.10**). That error ran
**0.46-0.53** all run while the teacher's own mean |action| is ~0.56, so the
default demands the student match the teacher to within 18% of the entire action
magnitude. Each trigger runs `actor.load_state_dict(actor_before_update)` and
invalidates the batch, so the student never learned from its own states. Raised
to **0.60**: rejections fell to **1/200**.

**c) A single rejection ratchets the handover shut.** Even at 1/200 rejections,
the teacher was still executing 90% at iteration 199 with student control 0.10.
The cause:

```python
handoff_floor = max(handoff_floor, recovery_execute_floor)   # monotone, never reset
beta          = max(beta, handoff_floor)                     # teacher execute prob
```

`handoff_floor` only ever increases, so ONE rejection anywhere pins the teacher
at >= `recovery_execute_floor` (0.9) for every remaining iteration. Fixed with
`--recovery_execute_floor 0.0`, which keeps the rejection and the teacher-only
recovery batches without ratcheting the handover.

*(Correction: `dagger_phase_coverage: False` was cited earlier as evidence of a
failed handover. It is not -- it is a config echo of the
`--dagger_phase_coverage` flag, which spreads environments across terrain start
phases. The evidence is `teacher_execute_probability` and
`student_control_fraction`.)*

## Step 2 is necessary, and measurably so

`PPO_AAM_FD/scripts/zero_context_columns.py`. During distillation the context
is a constant zero, so its weight gradient is zero and those weights never leave
their random initialisation. Measured on the first 70-wide distillation:

| | value |
|---|---|
| distilled context weight abs-max | **0.119** |
| `prive_warmstart`, which destabilised under fine-tuning | 0.00496 |
| output change from a unit-scale context, before zeroing | **0.564** |
| context-invariance after zeroing | **0.0** at x1, x10, x100, x1000 |

The distilled checkpoint's context weights were **24x larger** than the ones that
broke the earlier fine-tune. Zeroing is required, not cosmetic, and the script
refuses to write unless context-invariance is exactly zero. It also clears the
optimizer state, whose stale moments would otherwise re-inflate the zeroed
columns on the first update.

## Step 3: two distinct causes of the "Phase 1 collapse"

It was never one bug, which is why single explanations kept failing.

**Cause 1 — the warm start itself (the `prive_warmstart` runs).** Its four/six
context columns carried weights that were never trained (constant-zero input ->
zero gradient), so they sat at random initialisation. Measured: abs-max 0.119 on
the distilled checkpoint, and feeding a unit-scale context shifted the policy's
output by **0.856**. Fixed by `zero_context_columns.py`; context-invariance is
now exactly 0.0 at context x1000.

**Cause 2 — exploration std (the distilled-policy runs).**

| checkpoint | `distribution.std_param` |
|---|---|
| distilled Phase 1 init | **0.30** |
| `headroom_priced_v1` (the one that fine-tuned healthily) | **0.049** |

Distillation leaves std at its exploration setting; a converged PPO policy sits
6x lower. With `action_scale = 0.004 m` that is roughly +/-1.2 mm of pure noise
per step against 4 mm of authority, so PPO's SAMPLED rollouts are dominated by
noise while the deterministic policy is fine: training logged lateral **0.208 m**
at iteration 1 where evaluation of the same checkpoint gives **0.047 m**.

The decisive tell: metrics degraded during the 50-iteration critic warmup, when
the actor was FROZEN and could not have been damaged by its own updates. That
points at the sampling distribution, not the update rule.

Fixed with `--resume_std 0.05` (`--init_std` cannot do it: the checkpoint
overwrites the distribution at load). Result: ground contact recovered to 0.918
and cut-height error to 0.0137 m, both previously collapsing.

**What did NOT explain it**, each ruled out by a control rather than argument:
payload (the no-payload arm collapses identically), learning rate (the adaptive
schedule drove every arm to ~1e-5, and the worst arm had the LOWEST max LR),
critic warmup alone (helps, does not cure).

## Open: the reward prefers ground contact to line tracking

With std fixed, PPO makes a clear trade at ~iteration 36:

| iteration | lateral | ground contact | head_alignment | lateral reward | total |
|---|---|---|---|---|---|
| 32 (actor frozen) | 0.418 | 0.254 | -1.17 | 5.17 | -0.17 |
| 40 | 0.654 | 0.988 | -6.14 | 2.83 | 5.99 |
| 60 | 1.246 | 0.871 | -5.41 | 2.11 | 4.08 |

Ground contact 0.18 -> 0.99 while lateral goes 0.05 -> 1.25 m and head alignment
0 -> -6.1. Total reward RISES through that trade, so PPO is optimising its
objective correctly -- the objective simply prefers planting the cutter over
holding the line. The distilled policy proves a better joint point exists
(lateral 47 mm AND worst-family ground contact 0.875), so this is a reward
balance question, not an infeasibility.

Also unexplained: total reward fell 5.51 -> -0.17 during the critic warmup while
the actor was frozen. A constant policy cannot degrade itself, so something
environmental or in the logging moves there, and it should be understood before
any Phase 1 number is trusted.

## Step 3 resolved: the trainer was the problem

`PPO_AAM_FD/scripts/train.py` forwards to `verge_task/scripts/train.py`,
which has **none** of the post-distillation machinery PPO-ROM and PPO-ID-FD
used (`PPO_ID_FD/README.md`, "Train"). Those flags exist only in
`PPO_ROM/scripts/train.py`:

```
--trajectory_regularized  --trajectory_local_coef 0.10
--trajectory_max_update_kl 0.05   --trajectory_max_reference_kl 0.10
--trajectory_actor_learning_rate 3e-6
--trajectory_critic_learning_rate 1e-4
--fixed_std 0.05  --gamma 0.97  --entropy_coef 0.001
--reset_critic_head_on_resume --reset_actor_optimizer_on_resume
```

So every Phase 1 attempt was a plain PPO resume with nothing anchoring it to the
distilled policy, and it behaved exactly as that predicts: lateral 0.05 -> 1.25 m
while total reward ROSE, i.e. PPO correctly optimising an objective that prefers
planting the cutter over holding the line.
`--trajectory_max_reference_kl` is the anchor that prevents it; the actor also
runs ~30x slower than the critic.

That script knew only two task families (`IDFD*` -> idfd, else -> rom), so the
ID-AAM-FD task fell through to the wrong actuator. Added a branch shaped like
the existing one.

**Result, nominal plant, cycle-aligned:**

| cycle | iterations | peak total | lateral @ peak | ground contact @ peak |
|---|---|---|---|---|
| 0 | 0-88 | 20.245 | 0.0323 | 1.000 |
| 1 | 89-172 | **20.576** | 0.0332 | 0.996 |

Stable and slightly improving. Lateral ~32 mm at peak, better than the distilled
policy's 47 mm deterministic evaluation.

## How to read these curves (an artifact that cost hours)

An episode is 47.3 s at a 0.0167 s step (~2840 steps) and each iteration collects
32 steps per environment, so **one episode spans ~89 iterations**. The logged
metrics therefore trace the WITHIN-EPISODE error profile: excellent just after a
reset, decaying through the episode, snapping back at the next one.

Consequences:

- A raw "first value vs last value" comparison compares different phases of that
  cycle and **manufactures apparent collapses**. Several readings earlier in this
  session were exactly that.
- It explains the otherwise impossible observation that metrics "degraded" during
  a critic warmup while the actor was FROZEN. A constant policy cannot degrade
  itself; the cycle was moving, not the policy.
- Genuine failures are still distinguishable: the unanchored run held lateral
  ~1.25 m **sustained across all phases**, far outside this run's 0.03-0.25 band.

**Always compare cycle peak to cycle peak.**

\chapter{System Parameters and Coordinate Mappings}
\label{app:system-parameters}

The kinematic structure, the cylinder-to-joint mapping and the calibrated cutter
Jacobian are derived in Section~\ref{sec:sys:kinematics} and are not repeated
here. This appendix records the quantities a reader needs in order to reproduce
a run and cannot read off those derivations: the rate of every layer, the limits
the command path enforces, and the geometry of the scored course. Every value
below is read from the shipped configuration or from a stored evaluation
record, and the source is named in each case.

\section{Rates}

Five different rates operate in this system and confusing them is the most
common way to misread a result. The control step is $\unit[1/60]{s}$, the
physics substep is half that because the environment runs with a decimation of
two, and every learned component operates on the $\unit[20]{Hz}$ grid at which
the reduced-order model and the identification data were sampled.

Two derived latencies follow from Table~\ref{tab:app:rates} and are used in
Section~\ref{sec:eval:delay}. Both belong to the offline AAM and the ID adapter
it fed, which is the earlier path of Section~\ref{sec:models:chain}. The AAM
consumes a history of $20$ rows on the $\unit[50]{ms}$ grid, so its input
window is exactly $\unit[1.0]{s}$ and no estimate at all is available for the
first $\unit[1.0]{s}$ after a reset; until then that adapter is bypassed and the
frozen inverse action is returned unchanged. Its output smoother averages five
consecutive predictions, which adds a further $\unit[250]{ms}$ of group delay.

The deployed \ppoAAMFD{} residual of Section~\ref{sec:ctrl:af-residual} has
neither latency and no inverse model to fall back to. Its encoder reads $20$
rows on the control grid, so its window is $\unit[333]{ms}$, the window is
carried in the observation and zero-filled at start rather than gated, and no
smoother is applied. Nothing is bypassed: the residual is exactly zero at
construction because its head is zero-initialised, so a zero-filled window
reproduces the frozen base rather than switching to another path.

The lead cap is the mechanism by which the reference governor prevents the
commanded target from running away from the measured state, and the c3 reserve
is enforced by the solver while headroom is still scored against the original
stroke, so the gate is not satisfied by moving the goalposts. The ID adapter's
residual bound is what made that path fail safe: an adapter output that is
invalid, uninitialised or late is replaced by zero, which returns the stack to
the frozen-inverse configuration rather than to an untested one. The deployed
residual fails safe by the same principle at a different site. Its correction is
bounded by $\alpha\tanh(\cdot)$ whatever the head produces, and setting
$\alpha$ to zero at evaluation time recovers the frozen base exactly, which is
the property the control arm of Section~\ref{sec:eval:attribution} relies on.

\section{Trajectories}

Each run receives its own reference trajectory, sampled rather than
scripted. Between twelve and twenty waypoints are drawn by Latin
hypercube sampling within the joint limits, and the arm moves between
them without dwelling, so that the data contains transitions rather than
long static holds. Segment durations are drawn from four speed classes,
slow ($1.5$--$\unit[2.5]{s}$), medium ($0.8$--$\unit[1.5]{s}$), fast
($0.3$--$\unit[0.7]{s}$), and variable ($0.5$--$\unit[2.5]{s}$), and
about a third of the runs receive additional exploratory perturbations
on top of the waypoint path.

An earlier version of this generator used four to eight waypoints with
dwell periods between them. It produced data in which the arm was
stationary for a large fraction of the time, which flatters any model
that learns to predict persistence. The current settings were chosen to
remove that easy mass of near-static samples, and the increase in
waypoint count is the single change that most improved the usefulness of
the batch.




\section{Execution and Logging}

Each run simulates $\unit[22]{s}$ of operation. The solver is the stiff
implicit \texttt{ode23t} integrator in accelerator mode with relative
and absolute tolerances of $10^{-2}$ and $10^{-3}$. The loose tolerances
are a deliberate throughput compromise, and their effect is bounded by
the consistency checks of Section~\ref{sec:data:diagnostics}. Output is
written on a fixed $\unit[0.05]{s}$ grid, giving 441 logged samples per
run, and the batch is checkpointed to disk every hundred runs so that a
failure late in a multi-day batch does not cost the whole collection.

For every run the archive stores the time vector, the five valve
commands, the four cylinder extensions, the four chamber pressure
differences, the four rod forces, the five joint positions and
velocities, the reference position and velocity signals, and
the complete parameter structure that produced the run. That last item
is what makes the batch usable for the latent-adaptation work: the
privileged plant descriptor $\bm{\xi}$ of
Section~\ref{sec:fund:domain-randomization} is not something that has to
be reconstructed later, it is recorded alongside the trajectory.

The cost quantifies the argument made in
Section~\ref{sec:fund:sim-data-source}. A single
$\unit[64]{s}$ open-loop run takes roughly $\unit[2000]{s}$ of wall time
on the collection machine, a real-time factor of about $0.03$. The
Simscape plant runs some thirty times slower than the machine it
models. No policy-optimisation loop that needs millions of environment
steps can be built on that, which is why the learned actuator
surrogates exist.

The split is at \emph{run} level rather than window level, and this is the
single most important property of the collection. Within one run the factor
vector is constant, so windows drawn from the same run are highly redundant; a

manifest stores the factor key of every run alongside its split label, so this
property is checkable rather than asserted.

\section{The Adaptation Module}

This section describes the offline AAM, the encoder trained against a latent
target in Chapter~\ref{chap:models}. The residual encoder deployed in
\ppoAAMFD{} is a different component, trained jointly with its head under the
reinforcement objective and against no target
(Section~\ref{sec:ctrl:af-encoder}).

The AAM is a causal one-dimensional convolutional network over the last $20$
rows of the $\unit[50]{ms}$ deployment observable. The input row is $18$
columns wide,
%
\[
  h_t = \bigl[\, q(5),\ \dot q(5),\ \Delta p(4),\ u_{t-1}(4) \,\bigr],
\]
%
and the trunk is four convolutional stages of width $64$ and kernel three, the
first carrying a $1\times1$ skip projection from $18$ to $64$ channels, each
stage normalised. A two-layer head maps the final $64$-channel activation to the
$2$-dimensional latent $\hat z$. The whole module is $42\,562$ parameters, which
is what makes $\unit[20]{Hz}$ inference affordable alongside $256$ parallel
environments.

The latent dimension is $2$ because the module regresses onto the frozen state
predictor's latent, which is $2$-dimensional by construction. This is the
structural reason the deployed latent decodes only one of the six physical
factors, and Section~\ref{sec:models:aam-content} treats it as a finding rather
than a configuration choice.

The ID adapter is deliberately small: a two-layer network of width $64$, mapping
a $30$-dimensional feature row to a $4$-dimensional residual, $76$ stored
tensors' worth of normalisation statistics included. Its feature row is the
inverse model's $28$ inputs concatenated with the $2$ latent components, which
is the pressure-inclusive contract discussed in
Section~\ref{sec:eval:standing}. Its output is bounded at $0.15$ per cylinder
(Table~\ref{tab:app:limits}) and scaled by a declared residual factor of
$0.25$. That factor applies to the ID-adapter results, which are the null result
of Section~\ref{sec:models:chain} and the latent arms of
Appendix~\ref{app:results}. It is not the deployed residual's authority.

The adapter checkpoint additionally stores the digests of the inverse and
forward models it was fitted against, so a latent adapter cannot silently be
paired with a different frozen actuator than the one it was trained for.

\section{The Deployed Residual}
\label{app:models:residual}

The residual of Section~\ref{sec:ctrl:af-residual} is the component every
adaptation result in Section~\ref{sec:eval:adaptation} is produced by, and it
shares nothing with the ID adapter above except the idea of a bounded
correction. It acts on the valve command, not on the inverse model's output,
and there is no inverse model in the stack for it to correct.

Its encoder $\phi$ reads $20$ rows of $(\text{base observation},
\text{previous action})$ on the $\unit[60]{Hz}$ control grid, a
$\unit[333]{ms}$ window carried in the observation vector rather than in a
buffer held inside the module. The head $g_\psi$ is a small multilayer
perceptron with a zero-initialised final layer, producing a per-cylinder
correction bounded by $\alpha\tanh(\cdot)$ at $\alpha = 0.5$. Together they
hold $53\,836$ trainable parameters against the $59\,588$-parameter frozen
base, and the latent width is $8$.

Every arm reported in Section~\ref{sec:eval:adaptation} was trained with the
same command, differing only in the training seed and, for the control arm, in
the flag that zeroes the history window: $256$ environments, $400$ iterations,
history $20$, latent dimension $8$, $\alpha = 0.5$, learning rate
$3\times10^{-4}$, and the rebalanced lateral kernel at standard deviation
$\unit[0.09]{m}$ and weight $4.0$. The evaluation plant is the mid-episode load
change: bimodal cutter mass at $1.0$ and $3.0$, step time $\unit[20]{s}$,
jitter $\unit[8]{s}$. Checkpoints are listed in
Table~\ref{tab:app:hashes}; every arm is scored at iteration $399$, its last,
under the rule declared before the campaign.

\section{The Observation Vector}

The policy observation is $66$ columns for every stack. \ppoAAMFD{} deploys
this same actor frozen and unmodified; its adaptation residual reads a history
window carried alongside the observation rather than appended to the actor's
input (Section~\ref{sec:ctrl:af-residual}). The $66$--$68$ row below records the
two latent columns of the earlier latent-conditioned design, retained for
reference.
Table~\ref{tab:app:obs} gives the layout by index. The final twelve columns are
the model-error block, and they exist because the policy is a memoryless
multilayer perceptron: it already observes the actuator's prediction and the
current measured extension, but forming the error between them requires
differencing across two steps, which a feedforward network cannot do. Without
these columns the standing model error of a learned actuator is invisible to the
policy no matter how long it trains.

Channel $46$ caused a campaign-scale failure. It carries truck speed, and with a frozen observation normaliser inherited from a
fixed-speed run its recorded standard deviation was zero. The normaliser divides
by that standard deviation plus a small constant, which multiplied the channel by
roughly one hundred everywhere except at the speed the statistics were collected
at. The policy scored perfectly at that one speed and collapsed at every other.
Freezing a normaliser is correct when resuming; freezing one whose statistics
were gathered under a narrower distribution than the one about to be trained on
is not.

\section{The Action}

The action is four-dimensional in every stack, and it does not mean the same
quantity in all three. Under \ppoROM{} and \ppoIDFD{} it is a desired cylinder
motion, and what converts it to a valve command is the actuator under test,
which is the only free variable in that pair. Under \ppoAAMFD{} the same
four-dimensional bounded action is read as the valve command itself, scaled to
span the admissible valve range, because the inverse model was removed from the
command path (Section~\ref{sec:ctrl:ppo-aamfd}). That difference is why no
table ranks \ppoAAMFD{} against the other two on task error. The limits enforced
between the action and the plant are given in Table~\ref{tab:app:limits}.

\section{The Reward}

The ten reward terms and their shaping functions are given in
Table~\ref{tab:ctrl:reward} and are not repeated here. Two weights behind that
table are the ones a reproduction is most likely to get wrong: contact loss is
weighted at $20.0$ and hard impacts at $20.0$, against a support reward of
$4.0$. The hard-impact
weight was introduced after the measurement described in
Section~\ref{sec:sys:gates}: the quantity was gated but not priced, and the
optimiser traded it away while its return rose.

\subsection*{Measurements Behind the Design Rules}

The three rules of Section~\ref{sec:ctrl:ppo} were each adopted after a measured
failure, and the figures are recorded here.

\emph{Gaussian shaping.} Measured on the lateral term at an error of
$\unit[0.50]{m}$, the gradient of $w\exp[-(e/s)^2]$ is $-2.07$ at $s=0.30$ but
$-0.004$ at $s=0.15$, a factor of $520$ weaker in exactly the region occupied by
the failing path families. The bounded shapes $B$ and $H$ of
Equation~\eqref{eq:ctrl:shapes} replace it, $B$ retaining the same gradient at
$\unit[0.5]{m}$ of error as at $\unit[0.05]{m}$ and $H$ buying quadratic
precision near zero where cut height needs it.

\emph{Sign convention.} Weighting the positive contact reward four-fold for the
worst quarter of environments made a contact quality of $0.49$ pay $7.84$
against $2.00$ for a quality of $0.50$, and collapsed worst-family contact
within a single training block. Worst-case weighting is therefore admitted only
on the non-positive terms.

\emph{Removed terms.} Removing the action-magnitude penalty produced the first
training block in a full session that did not degrade, improving the held-out
score from $1.2058$ to $0.3678$. In its earlier form the head barrier dwarfed
lateral tracking, so line following could never compete for the optimiser's
attention.

\emph{Logging.} The earlier stack logged an aggregate and a partial subset, with
the two largest lateral terms not logged at all, which is part of why a reward
term opposing the task survived thirteen campaigns. Every term is now logged
individually and by name.

\section{The Three \texorpdfstring{\ppoROM{}}{PPO-ROM} Acceptance Records}

Three acceptance records for \ppoROM{} exist in the project and they disagree,
so Section~\ref{sec:ctrl:ppo-rom} treats none of them as certifying the
checkpoint it selects. They are separated here.

The first is the pipeline's own documentation, which reports all eight gates
passing across the $2$ to $\unit[7]{km/h}$ range on three meshes. This is a
selection-time record for a different checkpoint than the one that chapter
describes. The second is an earlier six-mesh evaluation of the rebuilt pipeline,
reporting seven gates passing and ground contact failing at $0.6486$ against the

expectation into Chapter~\ref{chap:evaluation}. The third is the selection
record of the checkpoint of Section~\ref{sec:ctrl:ppo-rom} itself, measured on
the superseded $\unit[16]{m}$ rollout and marked provisional for that reason;
that checkpoint's full-length six-mesh revalidation was never run.

None of the three is the evidence used in Chapter~\ref{chap:evaluation}. The
closed-loop comparison there re-scores a single checkpoint per stack under one
protocol, at one speed, over the full path, on the same meshes and the same
eleven path families.

\section{Reproduction}

Every closed-loop number in Chapter~\ref{chap:evaluation} is produced by the
experiment scripts stored with the project under \texttt{experiments/E1}
through \texttt{experiments/E6}, each of which records the checkpoint, the mesh
set, the family set, the speed and the scored horizon in its own manifest. The
adaptation arms are trained and scored by
\texttt{PPO\_AAM\_FD/experiment\_scripts}, and the paired statistics of
Section~\ref{sec:eval:adaptation} are recomputed from the stored
per-environment reports under \texttt{outputs/rif\_delay} by
\texttt{experiments/E3/code/seed\_table.py}. The model-level results come from
the frozen collection of Appendix~\ref{app:data:frozen}.

Two things about the scope of that are stated here rather than left to be
discovered. The first is a distinction. Every table in this thesis is
reproducible from the frozen inputs, which ship with the project: the artifacts
of Table~\ref{tab:app:hashes}, the Simscape collections, and the frozen
IsaacLab collections of Appendix~\ref{app:data:frozen}. That is a different and
weaker claim than regenerating those inputs from the original Simscape
collection scripts, which is not attempted and not required, since the
collections themselves are the record. Reproduction here means recomputing every
reported number from the data that produced it.

The second is an exclusion. The reports written before $16{:}34$ UTC on
31~August record no plant configuration, so they cannot be attributed to a
plant. They are retained under
\texttt{outputs/rif\_delay/archive\_unrecorded\_plant} and no number in this
thesis is taken from them (Section~\ref{sec:eval:instrument}).

# ROM-B circle continuity fix

Date: 2026-07-26

## Final implementation

ROM-B now defaults to
`PPO2_ROM_PhysX/models/plant_reachable_trajectory_library_v3_circle_c3.json`.
The library is a deep copy of v3-large with exactly one changed object: the
circle's inverse-cylinder command and its measured-model projection metadata.

Unchanged:

- tool-space circle geometry;
- path speed and time scaling;
- PPO checkpoint and residual scales;
- DLS/cascade inner-controller code and gains;
- cylinder velocity filter (`beta=0.0`);
- ROM-B plant factors and randomization;
- deterministic truck supervisor;
- rewards, terminations, and certification gates;
- every non-circle trajectory.

## Mechanism

The source circle was closed in tool and cylinder position, but its largest
inverse-command second derivative occurred at path fraction 0.321, matching the
measured acceleration-heavy trajectory bin 3. Slowing the path, globally
scaling PPO residuals, disabling PPO, and filtering velocity alone did not
generalize across plant conditions.

The accepted candidate was generated by:

1. applying a periodic Savitzky-Golay filter to the unique circle command points;
2. projecting each command back through the existing measured
   cylinder-to-tool/clearance RBF model;
3. using a strong continuity prior so pointwise inverse projection cannot jump
   back to another inverse branch;
4. rejecting candidates that violate tool projection, clearance, head alignment,
   or command-curvature gates.

Selected offline configuration: periodic window 21, cubic polynomial,
projection prior 1.0.

| offline measurement | source/candidate result |
|---|---:|
| tool mean projection error | 2.11 mm |
| tool p95 projection error | 5.91 mm |
| tool maximum projection error | 13.62 mm |
| clearance-reference p95 shift | 6.06 mm |
| predicted minimum head alignment | 0.98630 |
| command-curvature p95 ratio | 0.499 |
| command-curvature maximum ratio | 0.302 |
| maximum normalized command jump | 0.0334 (source 0.0759) |

## Measurement-harness correction

During the first preflight attempt, the isolation parent kept an Isaac/Vulkan
application open while starting child Isaac processes and triggered a GPU
crash. Isolation is now orchestrated by `scripts/evaluate_isolated.py`, which
imports no Isaac/GPU modules. Each shard exclusively owns the GPU; assembly
runs only after every shard exits. Subset evaluations also use the canonical
five-shape seed index, so a circle-only audit reproduces the circle seeds from a
complete audit.

## Status

The circle implementation is fixed and preflight-ready without PPO training.
ROM-B as a whole is not newly certified until the full repeated-seed audit of
the installed c3 library completes.
